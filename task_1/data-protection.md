## 2. Механизм тегирования

### Схема тега

```
sensitivity : PUBLIC | INTERNAL | CONFIDENTIAL | RESTRICTED
category    : PII.PERSONAL | PII.SPECIAL | PII.FINANCIAL | HR | TECHNICAL
legal_basis : CONSENT | CONTRACT | LEGAL_OBLIGATION
retention   : P3Y | P5Y | P25Y | P75Y | P90D
masking     : NONE | PARTIAL | FULL | ENCRYPT
```

| Уровень | Что попадает | Требование |
|---|---|---|
| `PUBLIC` | Прайс, адреса, расписание | Без ограничений |
| `INTERNAL` | Номенклатура, внутренние документы | Только сотрудники |
| `CONFIDENTIAL` | ФИО, телефон, платежи | Шифрование, RBAC, аудит |
| `RESTRICTED` | Диагнозы, анализы, заключения | Шифрование поля, ABAC, полный аудит, MFA |

### Разметка в схеме БД

```sql
COMMENT ON COLUMN patient.full_name IS
  'sensitivity=CONFIDENTIAL;category=PII.PERSONAL;legal_basis=CONTRACT;retention=P3Y;masking=PARTIAL';

COMMENT ON COLUMN patient.diagnosis IS
  'sensitivity=RESTRICTED;category=PII.SPECIAL;legal_basis=CONSENT;retention=P25Y;masking=ENCRYPT';
```

### Разметка в контракте API

```yaml
components:
  schemas:
    PatientSummary:
      properties:
        full_name:
          type: string
          x-sensitivity: CONFIDENTIAL
          x-masking: PARTIAL
        diagnosis:
          type: string
          x-sensitivity: RESTRICTED
          x-masking: ENCRYPT
```

### Как тег влияет на поведение системы

Тег бесполезен, если остаётся декларацией. Он должен работать в четырёх точках:

**Хранение.** Поле с `masking=ENCRYPT` шифруется перед записью, ключ берётся из Vault.

**Выдача.** Сериализатор применяет маскирование по тегу, если у роли нет права на полное значение. Логика в одном месте, а не в каждом контроллере.

**Аудит.** Чтение поля уровня `RESTRICTED` порождает событие в неизменяемом журнале.

**Сборка.** Линтер сверяет схему с реестром тегов. Сборка падает, если поле не размечено или защищаемые данные уходят наружу без маскирования.

### Проверка в CI

```yaml
data-policy-check:
  stage: verify
  script:
    - dtag validate --schema openapi.yaml --policy policies/data-tags.yaml
    - dtag check-untagged --source src/models/
```

Проверяемые правила:

1. Каждое поле схемы размечено тегом
2. Поле с `PII.SPECIAL` не отдаётся наружу без `masking=ENCRYPT` или `FULL`
3. Ответ внешнего API не содержит идентификаторов чужих пациентов
4. Витрина для BI не содержит полей уровня `RESTRICTED` без обезличивания
5. Формат лога не включает полей `PII.*` без обфускации

Нарушение блокирует сборку, а не выводит предупреждение. Иначе правило будет игнорироваться.

## 3. Меры по потокам данных

Каждая мера привязана к проблеме из `data-problems.md` и нанесена на `dfd-to-be.drawio`.

| Точка потока | Проблема | Мера |
|---|---|---|
| Сбор анкеты | P-02 | Сократить форму до необходимого минимума |
| Регистрация пациента | P-01, P-06 | Переход на СУБД с шифрованием, суррогатный `patient_id` |
| Имена файлов и папок | P-05 | Отказ от файловой структуры, идентификатор вместо ФИО в путях |
| Доступ врача к журналу | P-08 | Правило ABAC «врач - свои пациенты», аудит чтения |
| Доступ ресепшена | P-08 | RBAC: расписание и контакты доступны, диагнозы нет |
| Хранение заключений | P-06 | Отдельное хранилище документов, шифрование объектов, ссылки с ограниченным сроком |
| Передача в лабораторию | P-10 | Контракт API вместо файлов, mTLS, псевдонимизация: `sample_id` вместо ФИО |
| Внутренняя почта | P-12 | Контроль исходящих по тегу, замена вложений на ссылку |
| Обмен ККМ и учётной системы | P-11 | TLS и взаимная аутентификация вместо OLE |
| Excel кассира | P-13 | Устранить теневой контур, единый источник правды |
| Все операции чтения и записи | P-09 | Централизованное журналирование, неизменяемый лог, алертинг |
| Выгрузка в озеро данных | P-14 | Обезличивание в ETL, прослеживаемость от источника до витрины |
| Жизненный цикл данных | P-16 | Срок хранения из тега, автоудаление, процедура по запросу пациента |

## 5. Что даёт результат раньше всего

Полная программа занимает год. Три меры реализуются в первые недели и снимают наибольший риск.

**Сократить анкету.** Данные, которые не собраны, невозможно потерять.

**Убрать ПДн из имён файлов и папок.** Переименование по суррогатному идентификатору закрывает утечку через листинг каталога и метаданные бэкапа. Новая архитектура для этого не нужна.

**Включить журналирование доступа.** Пока аудита нет, компания не знает, происходит ли утечка прямо сейчас.
